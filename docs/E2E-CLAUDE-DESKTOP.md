# Сквозная (E2E) проверка расширения через Claude Desktop (Dispatch)

Документ для **Claude Desktop в режиме Dispatch** (работа на компьютере пользователя: терминал, файлы, Firefox).
Цель — пройти **все функции** расширения «Claude Exporter» в настоящем Firefox, автоматически проверить результаты на диске и составить отчёт о багах.

## Промпт для запуска (вставить в Claude Desktop → Dispatch)

```
Прочитай файл C:\Users\User\Desktop\claude export\claude-exporter-ff\docs\E2E-CLAUDE-DESKTOP.md и выполни его целиком, по порядку.
Работай самостоятельно: ставь расширение в Firefox, проходи все сценарии T00–T12, после каждой группы запускай
`npm run verify -- --since 20`, всё записывай в docs\E2E-REPORT-<сегодняшняя дата>.md по мере выполнения.
Соблюдай правила безопасности из раздела 1. В конце дай краткую сводку: сколько сценариев PASS/FAIL/BLOCKED и список багов по серьёзности.
```

## 1. Правила безопасности (обязательно)

1. **Только чтение на claude.ai.** Не удалять и не архивировать чаты, проекты, скиллы, память, артефакты. Не менять настройки аккаунта (можно только открывать страницы Settings). Не нажимать «Delete», «Archive», «Remove», «Disconnect», «Share», «Publish».
2. Экспорты содержат личные переписки: **не отправлять их никуда**, не вставлять их содержимое в отчёт. В отчёте — только имена файлов, счётчики, тексты ошибок и структура. Для примера текста используйте первые 5–10 слов, не больше.
3. Ничего не удалять в `Загрузки`. Перед стартом старую папку `ClaudeExport` **переименовать** (не удалять): `Rename-Item "$HOME\Downloads\ClaudeExport" "ClaudeExport.bak-<дата>"`.
4. Не вводить пароли и не обходить логин: если Firefox не залогинен в claude.ai — остановиться и попросить пользователя (`BLOCKED`).
5. Файл `~/.claude/.credentials.json` **не открывать и не читать**, даже для проверки. Проверять только, что расширение его не экспортировало (это делает `npm run verify`).
6. Если Firefox показывает диалог «Сохранить как…» (опция «спрашивать место») — сохранять в `Загрузки\ClaudeExport`.

## 2. Окружение

| Что | Значение |
|---|---|
| Проект | `C:\Users\User\Desktop\claude export\claude-exporter-ff` |
| Готовая сборка | `C:\Users\User\Desktop\claude export\claude-exporter-0.8.0.xpi` (или `manifest.json` из папки проекта) |
| Результаты | `C:\Users\User\Downloads\ClaudeExport\` |
| Проверка результатов | `npm run verify -- --since <минуты> [--json <файл>]` в папке проекта |
| Браузер | Firefox (Windows 11), залогиненный в claude.ai |

Как смотреть ошибки расширения:
* страница полного экспорта / popup: `F12` → вкладка **Консоль** (popup: правый клик по иконке → «Исследовать всплывающее окно», либо откройте `moz-extension://…/popup/popup.html` во вкладке);
* фон: `about:debugging#/runtime/this-firefox` → у расширения кнопка **Изучить**.
Любая красная ошибка в консоли во время сценария = баг (с текстом ошибки).

## 3. Формат отчёта

Создайте `docs/E2E-REPORT-<дата>.md` и дополняйте по ходу:

```
| ID | Сценарий | Результат (PASS/FAIL/BLOCKED) | Что видно / ошибка | Доказательство |
```
Для каждого бага: **ID, серьёзность** (S1 — потеря данных/крах/секреты в экспорте; S2 — функция не работает; S3 — неверный результат/неудобство; S4 — косметика), **шаги воспроизведения**, **ожидалось / получилось**, **текст ошибки из консоли**, имя файла-доказательства (скриншот в `docs/e2e-shots/`, вывод `npm run verify`). Не пытайтесь чинить код — только находить и описывать (если пользователь явно не попросил иначе).

## 4. Сценарии

Отмечайте каждый как PASS / FAIL / BLOCKED. «Ожидание» — критерий PASS.

### T00. Подготовка (терминал, папка проекта)
1. `npm test` → **все тесты зелёные** (≈140). `npm run lint` → 0 ошибок (8 предупреждений про `eval` в `vendor/` — норма). `npm run build` → создаётся `web-ext-artifacts\claude_exporter-0.8.0.zip`.
2. Переименовать старую `Downloads\ClaudeExport` (см. правила).

### T01. Установка
1. `about:debugging#/runtime/this-firefox` → удалить старую версию расширения → «Загрузить временное дополнение…» → выбрать `.xpi` или `manifest.json`.
2. **Ожидание:** в карточке «Claude Exporter», версия `0.8.0`, ошибок нет. На панели появилась иконка. Открылась вкладка полного экспорта (только при первой установке).
3. Открыть `claude.ai` в новой вкладке и убедиться, что вход выполнен.

### T02. Popup: состояния
1. На `claude.ai/recents` (не чат): popup показывает блок «Recent chats» с ≤5 чатами (новые сверху), блока «Current chat» нет, кнопка «Export selected (0)» неактивна.
2. Кликнуть по строке чата (не по галочке) → галочка ставится, счётчик растёт. Кнопка ↻ обновляет список.
3. Открыть любой чат: в popup появился «Current chat» с названием без « - Claude».
4. Закрыть все вкладки claude.ai, оставить другую (например, example.com): popup предлагает «Open claude.ai»; кнопка открывает claude.ai.
5. **Ожидание:** ни одной ошибки в консоли popup.

### T03. Popup: экспорт
1. На странице чата: включить Markdown, выключить PDF → «Export this chat». **Ожидание:** сообщение «Saved 1 chat(s)…»; в `Downloads\ClaudeExport\chats\` появился `.md`; если в чате были артефакты — файлы в `artifacts\<чат>\`.
2. Включить только PDF → экспорт → появился `.pdf`, открывается в просмотрщике, кириллица читается.
3. Выбрать 2–3 из «Recent chats» → «Export selected (N)» → файлы всех чатов, **нет** `index.md`.
4. Выключить и Markdown, и PDF → сообщение «Choose a format…», файлов нет.
5. Запустить `npm run verify -- --since 20`. **Ожидание:** `FAILED` быть не должно (WARN допустимы, разберите каждый).

### T04. Полная страница: чаты
1. Иконка → «Полный экспорт» (или «Open full export»). Нажать «Load chat list». **Ожидание:** счётчик «Total chats: N» совпадает с реальным числом чатов (сверить: список в `claude.ai/recents` до конца прокрутки; допустимо расхождение ≤ архивные/временные — опишите).
2. Фильтры: поиск по слову из названия (счётчик «To export» уменьшается); фильтр проекта; «By period» с датами и переключателем created/modified — проверить границы (чат, изменённый именно в граничный день, должен попасть); «Selected» — отметить 3 чата, «Select all visible», «Clear selection».
3. Экспорт **выбранных 5–10 чатов** в ZIP (Markdown + PDF, артефакты файлами). **Ожидание:** ZIP `ClaudeExport\claude-export-<дата>.zip`; сообщение «Done: chats N, files F, errors 0».
4. **Открыть ZIP двойным кликом в проводнике** (не 7-Zip!) → должен открыться; распаковать («Извлечь всё…») без ошибок «путь слишком длинный».
5. Режим «Separate files», папка `E2E` вместо `ClaudeExport` → файлы в `Downloads\E2E\<дата>\…`.
6. Опции: включить Thinking и Tool calls → в `.md` есть блоки `**Thinking**` и `*[tool] …*`; отключить YAML → нет `---` в начале; «Artifacts inside chat» выключить при включённых файлах → в чате только ссылка `→ ...`, без кода.
7. «Ask where to save (ZIP only)» → появляется системный диалог; сохранить в `Downloads\ClaudeExport`.
8. Запуск экспорта ≥ 20 чатов и нажатие «Cancel» посередине → «Cancelled, nothing saved.», файлов не появилось, кнопки снова активны.
9. `npm run verify -- --since 30 --json docs\verify-T04.json`. **Ожидание:** нет FAIL.

### T05. Артефакты
1. Вкладка «Artifacts» → загрузить список чатов → выбрать чаты с артефактами → включить «All versions» и «Download attached files» → экспорт. **Ожидание:** `artifacts\<чат>\<файл>` с правильным расширением (`.md/.html/.py/.jsx`…), `versions\<имя>.v1…`, `attachments\…` (открываются как картинки/PDF), `artifacts\index.md`.
2. Блок «Artifacts page»: число «Artifacts on the page: N» должно совпасть с числом на `claude.ai/artifacts`. Кнопка «Export all artifacts from the Artifacts page» → `user-artifacts\…`, сообщение «Done: artifacts A from C chats, not found M, errors E». **Ожидание:** `A + M ≈ N`; если `M > 0` — записать причины из `errors.log`.
3. Открыть 2–3 файла артефактов и сравнить с тем, что показывает claude.ai (заголовок, начало и конец текста).

### T06. Проекты
1. Вкладка «Projects» → «Load projects» → список совпадает с проектами в claude.ai. Снять галочку с одного → «Selected projects» уменьшился.
2. Экспорт. **Ожидание:** `projects\<имя>\knowledge\…` (текстовые файлы знаний), `files\…` (PDF/картинки; PDF открывается), `INSTRUCTIONS.md` (если инструкции заданы), `_project.json`. Снять «Include project files» → папки `files\` нет.

### T07. Память и скиллы
1. Вкладка «Memory & Skills» → экспорт. **Ожидание:** `skills\index.md` (таблица со всеми скиллами), `skills\<имя>\DESCRIPTION.md`, `memory\memory-raw.json`; если память пуста — заметка «The memory text is empty…». Снять обе галочки → кнопка неактивна.

### T08. Claude Code и файлы
1. Вкладка «Claude Code & files». кнопка выбора («Обзор…») под «Claude Code folder (.claude)» → в окне выбора папки вписать `C:\Users\User\.claude` → «Выбор папки». (Firefox может спросить «Загрузить N файлов?» — подтвердить.) **Ожидание:** строка «Sessions: S, memory files: M, skills files: K, …»; в таблице сессии с осмысленными заголовками и проектами.
2. Отметить 2 сессии (режим «Selected»), оставить «Also export» → экспорт. **Ожидание:** `claude-code\<проект>\chats\…md`, `…\artifacts\…` (файлы, созданные Claude Code), `claude-code\memory\…`, `claude-code\skills\…\SKILL.md`, `claude-code\CLAUDE.md` (если есть).
3. `npm run verify -- --since 15`: **обязательно** PASS «no credential/settings files». Дополнительно в терминале: убедиться, что в ZIP нет ни `.credentials.json`, ни `settings.json`.
4. Если у пользователя есть официальный экспорт (ZIP от «Export data»): выбрать его во втором поле → «Conversations: N» → экспорт → `official-export\chats\…`. Если архива нет — `BLOCKED` (не критично).

### T09. Диагностика
1. Блок «Diagnostics» → «Run diagnostics». **Ожидание:** «Report saved: Downloads/ClaudeExport/diagnostics-….json», в блоке сводка `[OK ]` по всем шагам.
2. `npm run verify -- --since 10`. **Ожидание:** раздел `Diagnostics` без FAIL (в отчёте нет id и почты).
3. «Start recording» → открыть `claude.ai/settings/capabilities`, `claude.ai/artifacts`, любой проект → вернуться → «Stop recording and analyze». **Ожидание:** появился новый отчёт, в сводке есть строка `[OK ] recorded recorded=N, replayed=M`.

### T10. Язык
1. «Settings → Language» → Русский. **Ожидание:** все вкладки, кнопки, подсказки, сообщения «Готово…», popup — на русском; **нет** сырых ключей вроде `tab_local` и **нет** оставшегося английского в интерфейсе (кроме названий «Markdown», «PDF», «ZIP»).
2. Вернуть English; перезагрузить страницу — выбор сохранился.

### T11. Устойчивость
1. Открыть popup при **закрытой** вкладке claude.ai → корректное сообщение (T02.4).
2. Вкладка claude.ai была открыта **до** установки расширения (после «Удалить»→«Загрузить» заново): «Load chat list» должен сам перезагрузить вкладку и загрузить список, без ошибок.
3. Выйти из аккаунта claude.ai (только если пользователь разрешил; иначе пропустить/BLOCKED) → «Load chat list» показывает понятную ошибку `Error: HTTP 401/403…`, страница остаётся рабочей.
4. Убрать разрешение на claude.ai (`about:addons` → расширение → Разрешения) → при открытии страницы появляется «Allow access to claude.ai».
5. Экспорт большого числа чатов (≥ 100, ZIP, только Markdown): не зависает, прогресс идёт, итоговый ZIP открывается проводником.

### T12. Итоговая проверка файлов
1. Открыть в проводнике **каждый** созданный ZIP двойным кликом; открыть 3 разных `.md` в редакторе (заголовки `# Human — …`/`# Claude — …`, YAML в начале, ссылки на артефакты `→ ...\файл` ведут на существующие файлы); открыть по одному `.pdf`.
2. `npm run verify -- --json docs\verify-final.json`. **Ожидание:** `TOTAL: OK`. Все WARN перечислить в отчёте с объяснением.

## 5. Известные ограничения (не считать багами)

* Содержимое файлов скиллов и новой памяти («melange») не экспортируется — нет известного адреса (в отчёте будет только список скиллов и пустой текст памяти).
* Экспорт из popup прерывается, если popup закрыть (клик мимо окна) — ограничение Firefox.
* Firefox сохраняет только внутрь папки «Загрузки».
* Длинные названия сокращаются в именах файлов (полное название — в самом файле и в `index.md`).
* Расширение временное: после перезапуска Firefox нужно загрузить заново (если не подписано).
* Предупреждения `eval` в `vendor/jszip.min.js`, `vendor/pdfmake.min.js` — чужие библиотеки.

## 6. Что вернуть пользователю

1. Путь к `docs/E2E-REPORT-<дата>.md`.
2. Сводка: `PASS n / FAIL n / BLOCKED n`.
3. Список багов по серьёзности (ID — заголовок — шаги — ожидалось/получилось).
4. Вывод последнего `npm run verify` (без содержимого чатов).
